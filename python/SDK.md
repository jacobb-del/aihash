# aihash — Python SDK

Доказуемый журнал работы ИИ-системы. Реализация формата [aihash/1](../FORMAT.md).

## Подключение

```python
import aihash

log = aihash.open("./journal", realm="romashka-prod", stream="voice-eu-3")

log.record({"actor": "assistant",
            "output.text": "возврат придёт в течение 5 дней",
            "config.model": "gpt-4o-2026-02-11"})
```

Дальше 364 дня в году ничего не происходит.

### Через OpenTelemetry

Если наблюдаемость уже стоит — а у целевой аудитории она стоит почти всегда:

```python
import aihash.otel
aihash.otel.install("./journal", realm="romashka-prod")
```

Дальше приложение пишет трассировку как обычно; каждый завершённый span становится записью в цепи. Мы работаем рядом с наблюдаемостью, а не вместо неё: существующие экспортеры не трогаются.

## Сохранность

```bash
aihash retention --root ./journal --set-years 7 --set-sink s3://romashka-evidence
aihash seal --root ./journal --archive
aihash retention --root ./journal
```

```
Журнал romashka-prod
  Политика: хранить 7 лет, режим compliance
  Записи с 2026-07-28 по 2026-07-28 (1 суток)
  Запечатано: 1 суток
  В архиве:   1 суток, приёмники: local
              самая ранняя запись защищена до 2033-07-28
  Пробелов нет: всё завершившееся закрыто и уложено.
```

Это ответ на первое сообщение продукта. Ненулевой код возврата означает пробел: сутки прошли, а закрыть или уложить их забыли.

**Архив — сам по себе валидный журнал.** Его проверяет тот же верификатор без единой правки, включая бинарь на Go.

| Приёмник | Что защищает | Кто принуждает |
|---|---|---|
| `local:/путь` | снимает право на запись | файловая система — от случайности и от скрипта, но не от владельца каталога |
| `s3://корзина/префикс` | Object Lock, режим COMPLIANCE | AWS: до истечения срока объект не удалит даже владелец учётной записи |

Приёмник S3 **отказывается писать в корзину без включённого Object Lock**: худший исход — клиент считает себя защищённым, не будучи защищённым.

## Известное противоречие: вычёркивание и неизменяемое хранение

Две возможности продукта конфликтуют, и об этом надо знать **до** внедрения, а не после запроса на удаление.

Вычёркивание правит журнал, но не копию, уже уложенную в архив. Что можно сделать:

| Приёмник | Достигает ли вычёркивание архива |
|---|---|
| `local:` | да, после `aihash archive --date … --force` |
| `s3://` в режиме `GOVERNANCE` | да, привилегированным доступом |
| `s3://` в режиме `COMPLIANCE` | **нет.** Прежнюю версию не удалит никто до истечения срока хранения |

Это не недоработка, а прямое следствие того, ради чего режим `COMPLIANCE` и выбирается: его нельзя обойти, в том числе владельцу. Команда `aihash redact` обнаруживает уже уложенные сутки, называет затронутые приёмники и возвращает ненулевой код, если удаление невозможно, — чтобы это выяснилось у вас, а не у проверяющего.

**Как выбирать.** Если персональные данные попадают в журнал и вы обязаны исполнять требования об удалении:

1. Не кладите поля с персональными данными в журнал вовсе — записывайте их идентификаторы, а содержимое держите в системе, где удаление возможно.
2. Либо укладывайте в архив в режиме `GOVERNANCE`, приняв, что его можно обойти привилегированным доступом.
3. Либо ограничьте срок хранения тем, что вы готовы удерживать при любом запросе.

Правильное решение на уровне формата — шифрование значений полей ключами вне архива: удаление ключа делает значение невосстановимым даже в неизменяемом хранилище. Это изменение формата, и в версии 1 его нет.

## В день, когда прилетела претензия

```bash
aihash seal --root ./journal
aihash explain --root ./journal --stream voice-eu-3 --seq 3 --out ep.seal
```

Внутри `ep.seal` — выписка на одну страницу и всё, что нужно для проверки. Оппонент проверяет у себя:

```bash
aihash verify ep.seal
```

Без сети, без наших серверов, без учётной записи. Пакет весит около 6 КБ и содержит только раскрытые записи — остальной журнал в нём отсутствует и по нему невосстановим.

## Вычёркивание по запросу на удаление

```bash
aihash redact --root ./journal --stream voice-eu-3 --seq 1 \
  --fields customer.name,customer.phone --reason "запрос на удаление"
```

Значение и соль удаляются, лист дерева остаётся. Отпечаток записи не меняется, пломба продолжает сходиться. Само вычёркивание записывается в цепь: датировано и объяснено.

## Что решено и почему

**Асинхронная запись не возвращает номер.** `record()` возвращает `seq` только при `sync=True`. В асинхронном режиме номер ещё не присвоен — он присваивается в момент долговечной записи, а не вызова. Иначе падение процесса оставляло бы дыру в нумерации, неотличимую от подчистки.

**Переполнение очереди — громкая ошибка.** `Overflow`, а не тихий сброс события. Доказательственный журнал не вправе молча терять записи.

**Запечатанный отрезок закрыт навсегда.** `seal` отказывается закрывать текущие сутки: первая же запись после пломбы порвала бы отметку отрезка.

**Пломба ставится тремя способами сразу.** Отказ одного типа не отменяет остальные — ради этого их и три. Тип, который не удалось проверить офлайн, показывается как «не проверена», а не как «в порядке».

**Срок хранения отсчитывается от суток, а не от момента архивации.** Иначе поздняя укладка незаметно продлевала бы срок и прятала просрочку.

**Ключей нет.** Целостность их не требует. Проверка без подписи доказывает, что содержимое не менялось и существовало в указанном промежутке, но не доказывает авторство.

## Границы

| Тип пломбы | Состояние |
|---|---|
| `feed` | реализовано полностью, проверяется офлайн |
| `rfc3161` | запрос и хранение ответа реализованы; проверка подписи требует `openssl` и сертификата службы |
| `opentimestamps` | адаптер к `opentimestamps-client`; без него тип помечается недоступным |

Про S3 Object Lock тесты доказывают, что мы запрашиваем режим `COMPLIANCE` с верной датой и отказываемся писать в корзину без блокировки. Что блокировка работает — поведение AWS; локальный макет `moto` запоминает режим, но удаление пропускает, и выдавать это за проверку было бы обманом.

Маяк drand берётся по сети с мягкой деградацией: недоступен — отрезок пишется без него, нижней границы времени в выписке не будет.

## Разработка

```bash
python3 ../verifier/build.py            # страница-верификатор для пакетов .seal
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q
```

Порядок важен: `verifier/build.py` кладёт `aihash/assets/verify.html`, который вкладывается в каждый пакет доказательства. Без него пакет собирается, но получателю придётся искать верификатор самому — команда предупредит об этом.

`tests/test_vectors.py` сверяет библиотеку с векторами [spec/](../spec/) побайтово. Это главный тест: если он падает, реализация несовместима со спецификацией и всё остальное значения не имеет.
