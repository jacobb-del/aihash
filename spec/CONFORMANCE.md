# Конформанс

Реализация формата `aihash/1` считается соответствующей, если воспроизводит все девять наборов векторов побайтово **и** отвергает все отрицательные случаи.

## Проверить

```bash
python3 spec/tools/check.py
```

Код возврата 0 — расхождений нет. Ненулевой — расхождение с указанием конкретного места.

## Пересобрать векторы

```bash
python3 spec/tools/genvectors.py
```

Пересборка обязана давать побайтово те же файлы: соли выведены по документированному правилу, случайности в наборе нет. Если файлы изменились после пересборки — изменился формат, и это должно быть осознанным решением с повышением версии.

## Что в наборе

| Файл | Что проверяет | Почему включён |
|---|---|---|
| `01-varint` | LEB128 без знака | первое, что расходится между языками |
| `02-field-leaf` | лист поля | UTF-8, пустое значение, произвольные байты |
| `03-merkle` | дерево RFC 6962, n = 1…8, все пути принадлежности | нечётные n ловят дублирование последнего узла |
| `04-record` | содержательные отпечатки записей | сортировка полей, сборка дерева |
| `05-chain` | нулевое звено и цепь двух потоков | связывание seq, времени и содержимого |
| `06-redaction` | отпечаток до и после вычёркивания | ключевое свойство формата |
| `07-segment` | отметки трёх отрезков, включая второй отрезок потока | связывание отметок между собой |
| `08-day` | суточный корень и отметка | сортировка потоков, цель пломбы |
| `09-inclusion` | путь от поля записи до отпечатка под пломбой | содержимое пакета `.seal` |

Плюс восемь отрицательных случаев в `check_negative`.

## Порядок портирования на новый язык

Идти снизу вверх и останавливаться на первом расхождении. Ошибка на нижнем уровне даёт лавину расхождений выше, и искать её там бесполезно.

1. `varint` — 01
2. `H`, `lp` и лист поля — 02
3. Дерево и путь принадлежности — 03
4. Сортировка полей и `content_root` — 04
5. Нулевое звено и цепь — 05
6. Вычёркивание — 06
7. Отметки отрезка и суток — 07, 08
8. Сквозной путь — 09
9. Отрицательные случаи — принимать их запрещено

## Пять мест, где реализации расходятся чаще всего

1. **varint** — знаковое кодирование вместо беззнакового, либо неминимальная кодировка.
2. **Сортировка полей** — по строке в кодировке языка вместо байтов UTF-8. Для кириллицы и составных символов результат отличается.
3. **Нечётное дерево** — дублирование последнего узла по образцу Bitcoin вместо поднятия по RFC 6962.
4. **Повторное хеширование листьев** — в RFC 6962 `MTH` хеширует листья сама; здесь листья приходят готовыми.
5. **Пустое значение** — трактовка как отсутствия поля вместо значения нулевой длины.

## Эталонная реализация

[`tools/ref.py`](tools/ref.py) — нормативна для векторов, но не является библиотекой продукта: в ней нет буферизации, приёмников, пломб и обработки отказов. Она написана так, чтобы её можно было прочитать целиком и сверить со спецификацией строка в строку.

При расхождении между `ref.py` и [FORMAT.md](../FORMAT.md) прав документ, а код подлежит исправлению.
