# @aihash/aihash — TypeScript SDK

Доказуемый журнал работы ИИ-системы. Реализация формата [aihash/1](../FORMAT.md).

**Ни одной зависимости во время работы.** Только стандартная библиотека Node ≥ 18.

## Подключение

```ts
import { open } from "@aihash/aihash";

const log = await open("./journal", {
  realm: "romashka-prod",
  stream: "voice-eu-3",
});

await log.record({
  actor: "assistant",
  "output.text": "возврат придёт в течение 5 дней",
  "config.model": "gpt-4o-2026-02-11",
});
```

Дальше 364 дня в году ничего не происходит.

## Командная строка

```bash
aihash-ts seal    --root ./journal --anchor feed
aihash-ts explain --root ./journal --stream voice-eu-3 --seq 3 --out ep.seal
aihash-ts verify  ep.seal
aihash-ts redact  --root ./journal --stream voice-eu-3 --seq 1 \
                  --fields customer.name,customer.phone --reason "запрос на удаление"
```

## Гарантии, совпадающие с Python

Одинакового формата мало: две реализации не должны давать журналы с разными свойствами.

**Асинхронная запись не возвращает номер.** `record()` возвращает `seq` только при `{ sync: true }`. В асинхронном режиме номер ещё не присвоен — он присваивается в момент укладки на диск, а не вызова. Иначе падение процесса оставляло бы дыру в нумерации, неотличимую от подчистки.

**Переполнение очереди — громкая ошибка.** `Overflow`, а не тихий сброс. Проверка места и постановка в очередь идут в одном такте: иначе сотня одновременных вызовов проскакивает охрану целиком, потому что все они видят пустую очередь до того, как хоть один в неё попал.

**Дописать в запечатанный отрезок нельзя.** Пломбу ставит отдельный процесс по расписанию, поэтому отрезок может быть запечатан, пока поток держит его открытым. Проверка идёт на каждой записи, а не только при смене суток.

**Некорректный вызов не роняет поток записи.** Он отклоняет именно этот вызов и называет причину сразу. Отказ ввода-вывода останавливает поток целиком — писать дальше некуда.

## Совместимость

```bash
npm test
```

`test/vectors.test.ts` сверяет ядро с [spec/vectors](../spec/vectors) побайтово — те же файлы, по которым проверяются Python, Go и браузерный верификатор.

`test/cross.test.ts` идёт дальше чисел: журнал, написанный TypeScript, обязаны принять Python и бинарь на Go, а журнал, написанный Python, — принять TypeScript. Подделку в пакете из TypeScript обязаны поймать все три.

## Чего нет

**Штампа времени RFC 3161 и OpenTimestamps.** Реализована пломба `feed`; остальные два типа ставятся командой `aihash seal` из Python-версии. Причина — зависимости: полноценная проверка RFC 3161 требует разбора CMS, и тянуть ради этого стороннюю библиотеку в SDK без зависимостей неправильно. Проверяет их бинарь `aihash-verify`.

**Приёмников сохранности и политики хранения.** Это операционная задача, идущая по расписанию рядом с `seal`, а не в процессе приложения. S3-приёмник потребовал бы `aws-sdk` — цена, которую SDK без зависимостей платить не должен.
