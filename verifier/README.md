# Независимые верификаторы

Три реализации проверки. Каждая работает офлайн, ни одна не обращается к тому, кто выдал файл.

| Артефакт | Для кого | Требует |
|---|---|---|
| `dist/aihash-verify` | инженер, CI, эксперт оппонента | ничего |
| `dist/verify.html` | юрист, аудитор, страховщик | браузер |
| `dist/aihash-verify.js` | окружения, где Go нет | node |

`aihash-verify.js` проверяет **только пакеты `.seal`**. Разбор каталога журнала в общее ядро не входит: ядро не работает с файловой системой, иначе `verify.html` перестал бы быть файлом, который можно прочитать целиком. Журнал целиком проверяют бинарь `aihash-verify` и командные строки Python и TypeScript.

```bash
sh verifier/go/build.sh --all     # бинари под macOS, Linux, Windows
python3 verifier/build.py         # verify.html и aihash-verify.js
```

## Бинарь

```bash
aihash-verify ep.seal        # пакет доказательства
aihash-verify ./journal      # журнал целиком
aihash-verify -json ep.seal  # для CI
```

Код возврата: 0 — сходится, 1 — не сходится, 2 — файл не прочитан.

Только стандартная библиотека Go. Бинарь, который тянет чужой код, проверять доказательства не годится. `CGO_ENABLED=0`: на Linux получается полностью статический файл; на macOS Go всегда линкует `libSystem` — обойти это нельзя, у macOS нет устойчивого ABI системных вызовов, и «статический» там означает «без сторонних зависимостей».

## Страница

Открывается двойным щелчком с диска. Файл перетаскивается мышью и не покидает компьютер.

Сборка отказывается собирать страницу, если в ней найдётся `<script src=`, `<link`, `@import` или `http://`: самодостаточность проверяется, а не декларируется.

**SHA-256 написан в самом файле, а не взят из `crypto.subtle`.** При открытии с диска `crypto.subtle` доступен не во всех браузерах, а верификатор обязан работать двойным щелчком. Побочная выгода важнее скорости: алгоритм можно прочитать глазами и сверить со стандартом.

## Решения, общие для всех трёх

**Пакет `.seal` собирается без сжатия.** Тогда верификатору на JS не нужен распаковщик: чтение zip сводится к разбору каталога и нарезке байтов. Сжатые записи поддерживаются, если браузер даёт `DecompressionStream`, но по умолчанию до этого не доходит.

**Односторонняя граница времени не рисуется шкалой.** Если маяк в отрезок не записан, известна только верхняя граница; показывать её интервалом значит переоценивать. Шкала с двумя засечками появляется только когда обе границы есть.

**Локализация — до записи, но не до поля.** Отпечаток считается по записи целиком, поэтому определить, какое именно поле изменено, нельзя. Все три верификатора говорят это прямым текстом вместо того, чтобы называть поле наугад.

**Верификатор от стороны спора — не независимая проверка.** Страница и `VERIFY.txt` советуют взять файл из открытого проекта и сверить отпечаток; `build.sh` печатает отпечатки всех собранных артефактов именно для этого.

**Пломбы, которые нельзя проверить офлайн, помечаются «не проверена», а не «в порядке».** Бинарь дополнительно проверяет, что штамп RFC 3161 относится именно к этой суточной отметке, но подпись службы без её сертификата не подтверждает.

## Проверка

```bash
go test -C verifier/go ./...       # 10 наборов + 10 отрицательных случаев
node verifier/tests/conformance.js # 101 проверка
```

Обе сверяются с теми же [spec/vectors](../spec/vectors), по которым проверяется Python. Сверх этого `python/tests/test_cross_impl.py` прогоняет все три реализации по одним и тем же пакетам и требует совпадения вердикта — на исправном пакете, на подделанном, на порванной ленте и на журнале с удалённой записью.
